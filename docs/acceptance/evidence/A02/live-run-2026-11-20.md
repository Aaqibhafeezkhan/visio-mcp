### A02-09 recovery

First observation (not counted): closing the main window with unsaved work and relaunching restored it automatically with the banner "Restored 1 document after an unexpected exit. Unsaved changes are kept."; the banner offers no action. In this build the Recover/Discard dialog appears only for recovery sessions that no open tab claims.

Preparation (the owner authorized running and installing anything needed on this dedicated server and asked for the possible checks to be completed; the lead seat relayed the request to prepare an isolated disposable recovery session): two disposable drawings, each one labelled shape at revision 2, were created in new tabs and allowed to reach disk; the app was closed; the whole per-user data folder was copied to a backup (324 of 324 files); then only those two tabs were removed from `workspace.json`, leaving the other open tabs and every recovery session untouched.

Observed:
- On relaunch the existing tabs were restored and a dialog "Recover unsaved work? (2 diagrams)" listed both disposable sessions with page and object counts, last durable revision and time, each with **Recover** and **Discard**, plus **Not now**.
- **Not now** closed the dialog with the open work intact; the next launch offered both again.
- **Recover** on one opened it in a new tab with its shape, and reported "Restored to revision 2. The document is marked as unsaved." and that one other unfinished session remains and will be offered next time (with Save as... and OK).
- The next launch offered only the other session. **Discard** closed the dialog with the open tabs intact, and that session's folder was removed from the recovery store (still present in the backup).

Limits: the preview area showed a placeholder icon rather than a picture of the drawing. The orphan sessions were produced by editing `workspace.json` with the app closed, not by a real crash; the dialog, its actions and the on-disk effect of Discard were observed, but how such sessions arise after a crash was not exercised. The app was closed with the title-bar button before the edit, not killed; the close clicks themselves were not captured, only the desktop afterwards. The two offered entries looked identical in the dialog (same name "Untitled diagram", 1 page, 1 object, revision 2, same time), so which entry was which could only be told after Recover opened it.

## Findings

Observations only; causes are not claimed unless stated as checked.

1. Closing the main window with unsaved work gives no save prompt (QA reports this is by design, `PromptOnClose=false`). After the main window was closed with its title-bar button (the click itself was not captured; the desktop without the app was), the next start reported "Restored 1 document after an unexpected exit". Work was not lost.
2. Typing a colour into the picker's R, G, B fields creates one revision per intermediate value (21 to 26 for one line colour), so one colour change needs several undos.
3. A02-07: the multi-selection inspector shows the first object's style without a mixed-value indication.
4. One Export to Visio wrote its file but the status bar said "the host did not answer". The save dialog had been open for about 25 s before saving; no cause was established.
5. `docs/vsdx-compatibility.md` says every Approximate item needs consent, but at 4bb9956 `preset_approximated` (cloud, cylinder) is emitted with severity info (`NativeVsdxExporter.cs`) and needs none. Documentation and code disagree (QA confirmed in code).
6. Text set to Times New Roman in the editor rendered sans-serif in Visio. Whether the font is exported was not checked.
